### G1. The 6.2% slow tail - NEW CANDIDATE CAUSE 2026-09-18

In the spike's 336-request validation run, 6.2% of requests decoded below
100 tok/s (worst 33.9), clustered at 66-72K ctx with substantial outputs.

2026-09-18 finding that reframes this: transient 55-60 tok/s windows were
reproduced on BOTH engine versions and traced to swap churn - a second
client (gemma4) POSTing through the proxy during measurement, with
drain-before-swap letting both GPU containers coexist and starve decode.
The spike's run went through the proxy UNLOCKED, so the same contention
class is now the prime suspect for at least part of the tail (the 66-72K
clustering is unexplained by it, though - that part still smells like an
engine/config interaction).

Next step: re-run the equivalent workload LOCKED and see whether the tail
survives. If it does, characterize (ctx bucket, output length, effort) and
repro deterministically; if it doesn't, G1 closes as contention artifact.
